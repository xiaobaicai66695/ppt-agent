## Context

当前推荐模式在 Web 层按关键词选择 preset，再把 `DefaultSlides` 原样写入 outline，因此 preset 是 18 页时任务也固定为 18 页，示例描述还会进入主 Agent 上下文。背景只在少量 `content_type` 上由代码预填，主 Agent 缺少整套覆盖目标。另一方面，RuntimeMeta 的最近事件窗口只有 80 条，前端收到 SSE 快照后会替换已有时间线，导致早期 ToolCall 消失；压缩虽有计数事件，却未展示压缩差异，也没有把用户原始要求作为稳定锚点。

本变更跨越任务创建、DeepAgent prompt、模板 contract、RuntimeMeta/Compressor 与 Vue 工作台。现有任务 API、preset 显式选择行为和 Python 生成器接口需要保持兼容。

## Goals / Non-Goals

**Goals:**

- 推荐模式只借用模板视觉语言，页数和页面结构由用户意图动态决定。
- 主 Agent 能从真实背景目录中主动选择背景，整套演示形成有节奏的背景覆盖。
- 版式容量以目标密度和渲染上限表达，减少短文案造成的大面积空白。
- 模型上下文只接收生成进度 `done/total`，诊断数据继续留在运行时观测层。
- 前端可回看完整 ToolCall，并把压缩显示为带前后差异的独立事件。
- 压缩摘要优先保留原始用户目标和后续明确约束。

**Non-Goals:**

- 本次不新增 QA 流程或让 LLM 检查磁盘终态。
- 本次不下载新素材、不重做 Python 生成器视觉样式。
- 本次不改变用户显式选择 preset 时的固定模板脚手架语义。
- 本次不引入新的外部依赖或事件存储系统。

## Decisions

### 1. 推荐模式复用一次 LLM 意图分类结果

任务创建先执行现有 `ProcessUserIntent`，将合法的 `SuggestedTemplates`、`SuggestedPageCount` 和主题理解写入任务配置。推荐模式优先使用该结果选择 preset、palette 和背景主题，并创建 `recommended_style` outline：保留模板名、视觉参数和建议页数，但 `slides` 为空，由主 Agent 动态规划。

显式 `preset` 模式继续走 `template_scaffold`，保留 preset 的页面脚手架。模型不可用时推荐模式使用通用模板和有界默认页数作为降级，不再运行关键词打分器。这样既避免重复模型调用，也将“智能”决策集中到同一个结构化结果。

备选方案是裁剪或扩展 preset 的 `DefaultSlides`。该方案仍会把模板示例结构强加给主题，难以解决内容机械复制，因此不采用。

### 2. 背景采用语义分层规划与代码校验

主 Agent 获得实际可用的背景主题/图片引用、推荐主题和页面类型容量信息。规划指令用正向优先级描述三类页面：视觉叙事页优先背景；普通内容页在正文面板可读时使用；数据密集页优先清晰信息区。整套目标覆盖率为 45%-65%，封面、章节、引语、总结和图文页计入优先覆盖。

manifest 更新工具验证背景引用存在，并统计覆盖率；当推荐模式规划明显低于目标且已有推荐背景时，确定性补齐最高优先级的空背景页，同时轮换同主题图片。该补齐是失败兜底，正常路径仍由主 Agent写入背景选择。

备选方案是对所有页面强制背景。它会损害图表和 KPI 页的可读性，也无法形成视觉节奏，因此采用按页面语义分层的覆盖目标。

### 3. 容量 contract 区分目标密度与渲染上限

单页模板新增或统一 `target_*` 密度区间，`max_*` 仅作为可渲染安全上限。主 prompt 根据版式要求完整的信息单元、证据和结论，不再把短字数当作首要质量指标。生成器继续使用现有动态字号、换行和溢出保护消化区间内的差异。

首批调整信息页：`content_slide`、`summary_slide`、`two_column`、`three_column`、`card_grid`、`quote_slide`。图文和图表等已有合理容量的模板只统一文档语义。

### 4. 运行时信息分为模型进度与观测快照

RuntimeMeta 内部快照继续保存工具、token、告警和压缩统计，供 SSE 与诊断 UI 使用。注入模型的状态块改为专用的 `done/total` 视图；`manifest_validated` 事件 metadata 也只包含这两个数字。缺失文件、失败项等详细信息留在服务器日志/诊断字段和确定性终态判断中，不进入模型 handoff。

该分层避免用“删除 RuntimeMeta 能力”换取上下文精简，同时符合前端可观测性仍需丰富数据的要求。

### 5. 时间线使用追加合并而非快照替换

前端为 RuntimeEvent 提供稳定合并函数：优先按 event id 去重，旧数据没有 id 时使用时间、kind、name、status 和 detail 指纹。SSE 的 `recent_events` 仅作为增量尾部合并，任务会话接口返回的持久化历史作为完整基线。任务切换、断线重连和终态刷新都使用同一合并规则。

该方案保留后端 80 条热窗口以控制 SSE 体积，同时不牺牲已加载的早期 `read_file`、`edit_file`、搜索、manifest 和其他工具事件。

### 6. 压缩产出结构化用户意图锚点和差异

压缩前确定性提取首个真实用户请求，并收集后续用户明确新增的约束。摘要模型按结构化契约返回 `user_intent_summary`、`preserved_requirements`、`progress_summary` 和 `conversation_summary`；失败时使用有界的确定性摘要兜底。

压缩事件记录压缩前后消息数、token 数、移除消息数、节省 token/比例以及精简后的用户意图与保留要求。前端将其归类为 `compression`，使用专用对比区展示，而不是落入普通事件 JSON。

### 7. Prompt 采用正向目标、决策顺序和结构化输出

修改 prompt 时描述要达成的输出、选择依据、优先级和合法 schema，并用容量表与场景表覆盖分支。规则冲突通过单一决策顺序解决，不依赖不断追加“禁止某行为”的否定句。

## Risks / Trade-offs

- [推荐模式增加一次意图分类等待] → 复用 TaskManager 原本需要的分类结果，避免第二次调用；失败时走通用默认值。
- [背景覆盖提高后文字对比度下降] → 只给适配页面分配背景，并依赖现有玻璃面板和 palette 匹配；图表/KPI 页面保持低背景优先级。
- [容量放宽可能产生溢出] → `max_*` 仍保留渲染安全上限，增加模板 contract 测试并依赖动态字号。
- [前端合并导致内存增长] → 每个任务只保留持久化事件历史，按 id 去重；任务切换时释放非活动任务的视图状态。
- [压缩事件暴露过长用户文本] → 事件只保存有界摘要和约束条目，不保存完整原始 prompt。

## Migration Plan

1. 先增加兼容字段、合并函数和测试，旧任务缺少新字段时沿用现有展示。
2. 上线推荐模式与 prompt/contract 变更，显式 preset 路径保持不变。
3. 上线压缩事件详情和精简模型状态块，使用现有 SSE 事件结构承载新增 metadata。
4. 运行后端聚焦测试、全量 Go 构建、前端测试/构建和模板 JSON 校验。
5. 部署 Linux 后端与前端；回滚时恢复旧二进制和前端 dist，无数据库迁移。
