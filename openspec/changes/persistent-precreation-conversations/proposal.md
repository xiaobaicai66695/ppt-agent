## Why

工作台的统一输入区目前只在意图已经是 `create` 时才创建 PPT 任务。用户先描述一个主题、再补充“你决定主题和风格”等指代性消息时，服务端没有可恢复的上下文，导致后续路由和生成脱离最初需求。

这个界面定位为增强 PPT 创作能力的泛聊天 Agent；任务应是每次工作台会话的持久化容器，而非仅代表已经开始渲染的 PPT。

## What Changes

- 用户从工作台统一输入区发送第一条消息时，立即创建一个 task，并从该 task 开始持久化用户消息、Agent 回复、路由结果和上下文摘要。
- `chat`、`plan`、`create`、`fix` 都在同一 task 内推进；意图只决定当前阶段、可用操作和是否启动规划/渲染，不决定是否管理会话。
- 允许澄清、主题收敛、普通对话在已有 task 中多轮进行；当用户要求开始生成时，复用该 task 的完整上下文进入 Planner，避免重新创建孤立任务或丢失约束。
- 工作台任务列表明确区分对话/澄清、规划、生成、完成与失败状态，使非渲染会话也可恢复、继续和管理。
- **BREAKING**：统一消息入口和前端工作台将把 task ID 作为所有后续消息的会话锚点；旧的“路由成功后再新建 task”调用路径将被移除。

## Capabilities

### New Capabilities

- `unified-task-conversations`: 将工作台的每次自由输入创建为可持续恢复的 task，并在 task 内管理跨意图消息、上下文和 PPT 生命周期转换。

### Modified Capabilities

- 无。

## Impact

- 后端：`pkg/web` 的消息路由、任务创建与继续接口，`pkg/task` 的状态机与会话持久化，`pkg/db` 的 task 元数据/迁移，以及 Planner 输入构造。
- 前端：Dashboard 统一会话输入、任务列表状态/筛选、Home 创建入口及 API 类型。
- 运行与评测：新增跨轮上下文回归样例，覆盖“主题描述 → 澄清 → 委托 Agent 决定 → 生成”的完整链路；现有路由 benchmark 需增加 task 会话上下文维度。
