# PPT 生成流程

## 一、前端发起请求

用户在 `DashboardPage.vue` 的输入框中输入需求（如"做一个关于新能源汽车的行业分析报告"），点击提交后：

1. 前端调用 `POST /api/tasks`，传入 `query`（用户需求文本）
2. 如果用户通过 `ComposePage` 编排了完整大纲，则还会传入 `outline`（包含每页标题、布局类型、配色方案等）
3. 后端 `handleCreateTask` 接收请求，生成唯一 `taskID`

## 二、任务初始化（`task/manager.go`）

1. 创建工作目录 `workDir = {baseDir}/{userID}-{taskID}/`
2. **如果用户提供了 outline**（编排模式）：直接将 outline 写入 `tasks.json`，**跳过 AI 规划阶段**
3. **如果没有 outline**（纯文本模式）：创建空任务，AI 将在后续规划阶段生成 `tasks.json`
4. 初始化 `TaskState`，将任务状态置为 `running`
5. 启动 goroutine 运行 Agent

## 三、DeepAgent 主代理启动（核心编排层）

使用 `eino prebuilt/deep` 框架，主代理 `PPTTaskDeepAgent` 包含三个子代理：

| 子代理 | 职责 |
|--------|------|
| **SlideExecutor** | 调用 python-pptx 生成幻灯片 PPTX 文件 |
| **Reviewer** | 多模态视觉 QA 检查 |
| **Fixer** | 根据 QA 结果修复幻灯片问题 |

主代理持有以下工具：`edit_file`（读写 tasks.json）、`read_file`、`bash`（检查文件落地）、`search`（搜索真实数据）

## 四、主代理工作流（`master_instruction.tmpl`）

### 场景 A：有用户编排的大纲（ComposePage 模式）

```
第一步：读取 tasks.json + 模板文件 → 检查每页 description 是否完整
         ↓
第二步：补充内容 → 对 description 为空的页面，AI 生成详细内容（300-400字）
         ↓
第三步：分批并行生成 → 将 pending 任务按 5 个一批分批，同时发起所有批次
         ↓
第四步：文件落地确认 → bash ls 检查所有 pptx 是否已写入磁盘
         ↓
第六步：批量质检 → 一次性调用 Reviewer 审查所有 done 的幻灯片
         ↓
第七步：定点修复 → 对有 QA 问题的页面调用 Fixer，每页最多修复 2 次
         ↓
第八步：汇总结果
```

### 场景 B：纯文本需求（AI 自动规划）

```
第一步：选择模板 + 制定计划 → AI 根据需求选择模板，生成 tasks.json（包含每页 content_type/title/description）
         ↓
第二步：分批并行生成 → 同样按 5 个一批并行调用 SlideExecutor
         ↓
后续步骤同上
```

## 五、SlideExecutor 生成幻灯片（`executor_system.tmpl`）

这是真正生成 PPT 文件的地方：

1. **读取 tasks.json** 中当前任务的信息（content_type、title、description、palette）
2. **搜索真实数据**（如果需要）—— 使用 `search` 工具获取具体公司名、数据等
3. **调用 Python 生成代码**：
   - 导入 `generators` 包（位于 `skills/visual_designer/generators/`）
   - 根据 `content_type` 调用对应的生成函数（如 `generate_content_slide`、`generate_stat_slide` 等）
   - 每个生成函数接收 `palette`（配色方案）和具体内容参数
   - 使用 `save_slide()` 将幻灯片保存为独立的 `.pptx` 文件
4. **每生成一页立即调用 `single_qa_review`** 进行视觉 QA 检查
5. **每页最多 QA 2 次**：首次失败可修复一次，仍失败则跳过

## 六、视觉 QA 流水线（`qa_tool.go`）

这是确保 PPT 质量的关键步骤：

```
PPTX 文件
    ↓
pptx_qa_converter.py（调用 LibreOffice: PPTX → PDF）
    ↓
pdftoppm（PDF → JPEG，150 DPI）
    ↓
多模态 LLM 视觉审查（传入图片 + 系统提示词）
    ↓
返回 QA 报告：high / medium / low 级别问题
    ↓
修复建议（包含 python-pptx 代码片段）
```

QA 检查的问题类型包括：文字重叠（overlap）、文字溢出（overflow）、对比度不足（contrast）、间距不均（spacing）、对齐偏差（alignment）等。

## 七、Fixer 定点修复

根据 Reviewer 返回的 QA 报告，对指定页面进行修复：
- 读取原 PPTX 文件
- 使用 python-pptx 修改对应问题
- 重新保存并再次 QA 检查
- 每页最多修复 2 次

## 八、SSE 实时推送（`task/manager.go`）

整个过程中，后端通过 **SSE（Server-Sent Events）** 实时向前端推送事件：

| 事件类型 | 含义 |
|----------|------|
| `answer` | 主代理的 AI 响应文本 |
| `tool_call` | 工具调用（子代理派发、文件操作等） |
| `progress` | 任务进度更新（done/total 数量） |
| `file_ready` | 某个 PPTX 文件已生成 |
| `complete` | 任务全部完成 |

前端 `DashboardPage.vue` 通过 `EventSource` 监听这些事件，实时更新 UI（进度条、幻灯片卡片、事件日志）。

## 九、任务完成后

1. `TaskManager` 更新任务状态为 `completed`
2. 所有生成的 PPTX 文件路径写入任务记录
3. 触发 `onTaskComplete` 回调 → **学习用户风格偏好**（提取配色、布局、页数等特征）
4. 前端收到 `complete` 事件，停止 SSE 连接，显示最终文件列表

## 十、后续对话改进（Chat Bar）

任务完成后，用户可以通过底部的 **AI 对话栏** 继续改进 PPT。路由机制如下：

### 10.1 入口

前端在任务完成后点击"AI 对话"按钮，调用 `POST /api/tasks/{taskID}/continue`，传入用户的消息内容。后端 `handleContinueTask` 仅允许已完成（completed）的任务继续对话。

### 10.2 意图分类（Intent Routing）

核心实现在 `routeContinueIntent` 函数（`handler.go`），采用**规则快速路径 + LLM 精细分类**两层架构：

#### 第一层：规则快速匹配

检测高置信度关键词，直接返回对应意图：

- 命中"再加"、"添加"、"新增"、"加一页"等 → 意图为 `add_page`

#### 第二层：LLM 意图分类

若规则未命中，调用 `classifyIntentByLLM` 将用户消息 + 当前 PPT 结构摘要发送给 AI，AI 返回 JSON 格式的意图分析结果。

**LLM 支持的 5 种意图：**

| 意图 | 触发条件 | 示例 |
|------|----------|------|
| `fix` | 用户要求调整局部样式细节 | "第2页字体太小"、"换个颜色"、"对齐调整" |
| `regenerate` | 用户要求重新生成某些指定页面 | "第1页重新生成"、"第3张做得不好要重做" |
| `regenerate_all` | 用户对整体不满意，要求全部重做 | "全部重来"、"整体重新做" |
| `add_page` | 用户要求新增页面 | "再加一页"、"添加一个新页面" |
| `needs_clarification` | 用户反馈过于模糊，无法判断 | "不好"、"不太满意"、"难看"（未指明具体页面和问题） |

**fix 意图额外提取的 FixDetails：**

- `aspect`：视觉属性类型（font_size / color / alignment / spacing / position / style / text_content / layout / contrast / other）
- `detail`：具体调整描述，如"调大"、"换成蓝色"、"居中"
- `target_elements`：目标元素，如"标题"、"正文"、"所有文字"、"图表"

### 10.3 意图路由分发

根据意图类型分发到不同的处理函数：

```
用户消息
    ↓
routeContinueIntent() 意图分类
    ↓
┌─────────────────────────────────────────────┐
│ intent = "fix"                               │
│     ↓                                        │
│ runFixerContinue()                           │
│ - 读取 tasks.json                            │
│ - 根据 target_pages 找到目标任务              │
│ - 若未指定页码 → 修复所有已完成页面          │
│ - 构建完整上下文（tasks.json + 用户请求）    │
│ - 调用 RunFixerAgentWithCallback()            │
│   → Fixer Agent 读取 generator 源码          │
│   → 理解设计规范                            │
│   → 调用 Python 生成/修复代码                 │
│ - 实时推送 SSE（answer、tool_call）          │
│ - 更新任务状态为 fixed，刷新文件列表          │
├─────────────────────────────────────────────┤
│ intent = "regenerate"                        │
│     ↓                                        │
│ runDeepAgentContinue()                       │
│ - 读取 tasks.json                            │
│ - 将指定页码的 status 改为 pending            │
│ - 调用 RunSlideExecutorContinueWithCallback()│
│   → SlideExecutor 专用 prompt               │
│   → 只处理指定页码                           │
│   → 调用 Python 生成代码                      │
│ - 实时推送 SSE（answer、tool_call）          │
│ - 刷新文件列表，推送 complete                 │
├─────────────────────────────────────────────┤
│ intent = "regenerate_all"                    │
│     ↓                                        │
│ runDeepAgentContinue()                       │
│ - 将所有页面 status 改为 pending              │
│ - 调用 RunSlideExecutorContinueWithCallback() │
│   → targetPages=nil（全部）                 │
│ - 实时推送 SSE，推送 complete                 │
├─────────────────────────────────────────────┤
│ intent = "add_page"                          │
│     ↓                                        │
│ runDeepAgentContinue()                       │
│ - 读取 tasks.json                            │
│ - 在 tasks 末尾追加新 TaskItem               │
│ - status = pending，调用 SlideExecutor        │
│ - 刷新文件列表，推送 complete                 │
├─────────────────────────────────────────────┤
│ intent = "unknown"                          │
│     ↓                                        │
│ runDeepAgentContinue()                       │
│ - 将所有页面标记为 pending                    │
│ - 调用 SlideExecutor 全部重新生成             │
│ - 刷新文件列表，推送 complete                 │
├─────────────────────────────────────────────┤
│ intent = "needs_clarification"               │
│     ↓                                        │
│ 向用户返回澄清问题                            │
│ 等待用户进一步说明具体页面和问题               │
└─────────────────────────────────────────────┘
```

### 10.4 runFixerContinue 详细流程

1. 读取 `tasks.json`，获取所有任务信息
2. 解析 `route.TargetPages`，若为空则用正则匹配消息中的页码（如"第3页"），仍为空则取所有已完成页面
3. 根据 LLM 提取的 `FixDetails` 构建 QA 报告字符串
4. 对每个目标页面：
   - 验证 PPTX 文件存在
   - 将任务状态更新为 `StatusQADone`，`QAReport` 写入修复要求，`FixAttempts++`
   - **构建完整修复请求**：将完整的 `tasks.json` 内容 + 用户修复请求 + 目标页面信息打包成字符串
   - 调用 `RunFixerAgentWithCallback()` 启动 Fixer Agent，实时转发 SSE 事件
   - Fixer Agent 内部流程：读取 generator 源码 → 理解设计规范 → 调用 Python 生成/修复代码 → 输出修复结果
   - 修复成功后文件覆盖原 PPTX，状态更新为 `StatusFixed`
5. 写入 `tasks.json` 持久化
6. 调用 `refreshFileList()` 扫描工作目录，推送文件的 `file_ready` 事件
7. 汇总所有已完成文件，推送最终 `complete` 事件

### 10.5 runDeepAgentContinue 详细流程

1. 读取 `tasks.json`
2. 根据不同意图修改任务状态：
   - `add_page`：在末尾追加新任务，status = pending，记录 `targetPages = [新页码]`
   - `regenerate`：将指定页面的 status 改为 pending，`targetPages = 指定页码`
   - `regenerate_all`/`unknown`：将所有页面 status 改为 pending，`targetPages = nil`（全部）
3. 写入 `tasks.json` 持久化
4. **调用 `RunSlideExecutorContinueWithCallback()` 启动 SlideExecutor**，传入用户原始消息和目标页码
5. SlideExecutor 使用专用 prompt（`slide_executor_continue_instruction.tmpl`），只处理指定页码
6. SlideExecutor 实时推送 SSE 事件（answer、tool_call）
7. 生成完成后刷新文件列表，推送 `complete` 事件

### 10.6 SSE 事件推送

对话改进过程中同样通过 SSE 实时推送事件：
- `answer`：AI 分析结果和操作说明
- `tool_call`：intent_classifier 等工具调用
- `file_ready`：修复/新增的 PPTX 文件路径
- `complete`：本次对话处理完成

前端 `DashboardPage.vue` 通过 `connectChatSSE()` 监听这些事件，实时更新对话气泡和幻灯片列表。

## 流程图总结

```
用户输入需求
    │
    ▼
前端 POST /api/tasks
    │
    ▼
TaskManager 创建任务 + 工作目录
    │
    ├─ 有 outline ──→ 直接写入 tasks.json
    │
    └─ 无 outline ──→ 主代理规划 tasks.json
    │
    ▼
主代理（DeepAgent）调度
    │
    ├─ SlideExecutor（并行生成）
    │     │
    │     ├─ 搜索真实数据
    │     ├─ python-pptx 生成 PPTX
    │     └─ single_qa_review 视觉检查
    │
    ├─ Reviewer（批量质检）
    │     └─ PPTX→PDF→JPEG→多模态LLM审查
    │
    └─ Fixer（定点修复）
          └─ 根据QA报告修复问题
    │
    ▼
SSE 实时推送事件到前端
    │
    ▼
前端实时展示进度、文件列表
    │
    ▼
任务完成（或被用户终止） → 用户可对话改进
    │
    ▼
用户输入反馈（"第2页字体太小"）
    │
    ▼
handleContinueTask()
    │
    ▼
校验 task 状态为 completed 或 cancelled
    │
    ▼
routeContinueIntent() 意图分类
    │
    ├─ fix ──→ RunFixerAgentWithCallback() ──→ Fixer Agent 读取 generator → Python 修复
    ├─ regenerate ──→ RunSlideExecutorContinueWithCallback() ──→ 指定页码重新生成
    ├─ regenerate_all ──→ RunSlideExecutorContinueWithCallback() ──→ 全部重新生成
    ├─ add_page ──→ RunSlideExecutorContinueWithCallback() ──→ 生成新页面
    └─ needs_clarification ──→ 向用户返回澄清问题
    │
    ▼
SSE 推送修复/更新结果 → 前端刷新
```
