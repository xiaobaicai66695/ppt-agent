# 2026-08-03 JWT 鉴权与数据库故障解耦

## 问题

用户登录成功后访问受保护接口又被前端跳回登录页。后端原先在每次 JWT 验证后查询数据库刷新 `IsAdmin`；远端 MySQL 发生读取超时时，中间件将查询错误统一返回 401。前端收到 401 后清除 token 并跳转登录页，因此有效 JWT 被误判为过期。

## 修复

- 普通鉴权只验证 JWT 签名、有效期和必要 claims，不再依赖数据库可用性。
- 用户 ID、邮箱和管理员 claim 一并写入请求上下文，`/api/auth/me` 不再重复查询数据库。
- 管理员中间件继续从数据库读取最新权限；数据库错误返回 `503 auth_backend_unavailable` 和 `Retry-After: 5`，用户不存在返回 401，非管理员返回 403。
- `ValidateUser` 在数据库未初始化时返回明确错误，不再发生空指针风险。
- 增加认证和 Web 中间件测试，覆盖数据库不可用时普通 JWT 通过、管理员接口返回 503、篡改 token 返回错误及上下文 claims。

## MySQL 诊断

应用服务器到远端 MySQL 连续执行 10 次 TCP 建连与握手检查，4 次成功、6 次在 3 秒内超时；成功样本也出现约 1-2 秒延迟。错误发生在账号认证前，日志为 `i/o timeout` 而不是 `Access denied`，因此根因位于跨公网链路、数据库主机负载、连接队列或安全设备限流，不是账号密码。

建议将数据库迁移到同地域私网，或在数据库侧检查安全组/白名单、`max_connections`、活跃连接数、CPU、IO 和 MySQL 错误日志。
