# 005 运维、治理与可靠性交付决策

## 当前决策

影响运行行为的变更必须形成“本地验证 + Linux 构建 + 服务器部署 + 重启确认 + 线上最小冒烟 + 证据回填”的闭环；纯文档或不进入运行环境的改动可以免部署，但必须说明原因。

## 执行准则

- 默认服务器为 `remote-dev:/ppt/ppt-agent`，部署前确认目录、进程、端口和启动方式。
- 重启后至少确认新进程、目标端口、启动日志和 `/api/health`，不能只以复制成功作为上线成功。
- 前端静态资源和后端二进制必须从当前确认的源码/交付物构建，并在发布记录中标明实际部署目标，避免旧源码或错误路径覆盖运行版本。
- 线上冒烟按影响面选择最小链路：模板/背景查接口，鉴权查登录和受保护接口，生成链路创建低成本 1-2 页任务。
- 冒烟产生的临时任务、文件和中间产物要清理，避免污染用户任务列表和服务器目录。
- MySQL 运行基线为应用服务器本机 `127.0.0.1:3306`，应用日志需确认 `mysql_connected`。
- 缩略图转换、文件下载、manifest 恢复和 conversation 终态都属于交付可靠性，不应只看 Agent 是否返回完成。
- 清理历史代码或仓库产物前必须做引用扫描和最小构建验证。

## 取舍

上线闭环会增加每次运行行为变更的成本，但能防止“本地通过、线上旧进程仍在跑”“冒烟未测生成链路”“失败却归档 done”等问题。
