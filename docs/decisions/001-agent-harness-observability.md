# 001 Agent Harness 与可观测性决策

## 当前决策

PPT Agent 的运行可观测性以代码维护的 `RuntimeMeta` 和持久化运行事件为核心，而不是依赖自然语言过程描述。运行状态、工具调用、LLM 调用、token、交付进度和失败原因必须进入结构化事件流，并在前端 Timeline 中按需展示详情。

## 执行准则

- 后端负责产出可机器消费的运行元数据，前端只做轻量列表和按需详情加载。
- Timeline 列表保持轻量，完整 tool/LLM metadata 通过详情接口按需读取，避免 `/conversation` 返回大 payload。
- 正常轮询、manifest 对齐和可预期等待不应被渲染成告警；告警只用于真正需要用户或开发者关注的异常。
- 上下文压缩必须保留用户原始要求、交付锚点、页面状态和关键运行元数据，不能只留下自然语言摘要。
- 预算、熔断和失败诊断先以可观测信号落地，再根据真实 trace 调整硬阈值。

## 取舍

这样会增加事件模型、数据库记录和前端详情视图的维护成本，但换来可回放、可定位、可对账的 Agent 运行过程，避免“模型说完成但文件和状态不可证”的黑盒问题。
