# PPT Agent 前端工作台重构预研

## 1. 背景与结论

当前前端已经具备模板编排、任务流、渐进式预览、继续对话和管理能力，但视觉仍像多个独立页面拼接：营销首页、编排页、Dashboard 和管理页使用不同的信息节奏，大量相似卡片、边框、圆角和说明文字削弱了主任务，局部渐变、手写 SVG 和装饰背景又强化了模板化的“AI 产品感”。

本轮可行，且应直接重构。保留 Vue 3、路由、API、SSE 和业务状态，重做设计系统、应用壳、页面信息架构和主要交互表面。第一屏改为可直接创建演示文稿的工作区，不再把营销落地页作为主要入口。

## 2. 产品对标

| 产品 | 可借鉴模式 | 本项目采用方式 |
| --- | --- | --- |
| [Gamma](https://gamma.app/) | prompt-first 创建、生成过程持续反馈、结果以内容画布为中心 | 首页直接提供主题输入和模板入口；Dashboard 以进度和幻灯片结果为主 |
| [Canva Presentations](https://www.canva.com/create/presentations/) | 工具栏、页面缩略图、主画布和属性区职责稳定 | Compose 使用资源栏、页面轨道、属性面板三段结构，窄屏改为抽屉 |
| [Pitch](https://pitch.com/) | workspace/deck 组织、演示文稿封面优先、团队生产工具的高信息密度 | 最近任务和模板使用真实 16:9 预览，减少纯文字卡片 |
| [Linear](https://linear.app/) | 窄导航、克制层级、紧凑列表、命令优先 | 全局使用窄侧栏和紧凑顶栏，主操作保持单一且位置稳定 |
| [Notion](https://www.notion.com/product) | 内容优先、渐进披露、低装饰表面 | RuntimeMeta、Timeline、高级参数继续折叠，不抢占生成和预览区域 |

Pitch 与 Linear 的公开页面在 2026-08-03 可直接访问。Gamma、Canva、Notion 的公开页面抓取受到超时或风控限制，因此本预研只提炼公开可观察和行业通用的交互模式，不复刻其受保护的内部 UI、品牌素材或视觉细节。

## 3. 现状问题

1. `HomePage.vue` 是传统营销页，带装饰网格、光斑、渐变标题和功能卡，用户进入后仍需二次寻找真正的创建入口。
2. 页面缺少统一应用壳；首页、Compose、Dashboard、Admin、Auth 的导航、标题和操作位置不一致。
3. 大量页面区块都使用“白卡片 + 边框 + 阴影”，主内容、辅助信息和诊断信息的层级接近。
4. Compose 虽已响应式，但模板库、页面列表和属性编辑仍像三块独立表单，缺少编辑器式空间关系。
5. Dashboard 日志、进度、预览、聊天和诊断同时争夺注意力，用户需要多次扫描才能判断“现在做到哪、已经能看什么”。
6. 图标主要是组件内手写 SVG，尺寸、线宽和语义不统一。
7. 大型页面继续膨胀，视觉规则散落在 scoped CSS 中，后续迭代容易再次分叉。

## 4. 设计方向

### 4.1 视觉系统

- 以浅灰创作画布、白色工作面和近黑导航构成主层级，不使用装饰渐变、光斑或单一紫色主题。
- 主操作使用青绿色，信息链接使用蓝色，警告和强调使用珊瑚色，成功/失败保留语义色。
- 卡片圆角不超过 8px；页面区块默认不做浮动卡片，只为可重复的模板、任务和幻灯片预览使用卡片。
- 使用 Lucide Vue 统一图标，交互目标不小于 44px，图标按钮必须有可访问名称和 tooltip。
- 字体使用系统无衬线栈；标题、正文、标签和数字采用稳定字号层级，数字使用 tabular figures。
- 动画限定在 150-260ms，表达抽屉、选择、加载和结果出现，不做装饰性漂浮动画，并支持 `prefers-reduced-motion`。

### 4.2 应用结构

- 全局应用壳：窄侧栏承载首页、创建、任务和管理入口；顶栏显示当前位置、上下文操作和用户菜单。
- 首页：变为创建工作区，首屏直接输入需求、选择生成方式和最近模板，下面展示最近任务。
- Compose：左侧资源/模板，中间页面轨道，右侧属性编辑；主要生成动作固定在顶栏。
- Dashboard：左侧任务导航，中间生成轨迹与预览，右侧仅在宽屏展示上下文/聊天；移动端按内容优先折叠。
- Auth：简洁登录表单配真实模板预览，不再使用独立营销视觉。
- Admin：表格和指标优先，减少大卡片和装饰统计块。

## 5. 技术方案

- 新增可复用 `AppShell`、`AppRail`、`PageHeader`、`IconButton` 等轻量组件，不引入完整 UI 框架。
- 安装 `lucide-vue-next`，替换本轮触及页面的手写 SVG。
- 在全局样式中建立 primitive、semantic、component 三层 token；页面 scoped CSS 只保留布局差异。
- 保留现有 API、类型、SSE 和业务脚本，优先重构模板和样式；必要时拆分大型页面的纯展示组件。
- Home 在未登录或后端不可用时仍提供明确登录/进入工作台路径，不伪造任务数据。

## 6. 验证标准

- `npm run build` 通过，无 TypeScript/Vue 模板错误。
- 375、768、1024、1440 视口均无横向溢出，关键控制不被固定栏遮挡。
- Home、Auth、Compose、Dashboard、Admin 均共享同一设计语言和导航规律。
- 主要流程可键盘操作，焦点可见，图标按钮有名称，触控目标不小于 44px。
- 真实模板缩略图、任务缩略图、加载/失败/空状态均可区分。
- 使用浏览器截图和像素检查确认页面非空、布局稳定、无文本重叠和失控裁切。

## 7. 实施结果

本轮已按 `openspec/changes/ppt-agent-frontend-rebuild/` 完成实施：

- 新增统一 `AppShell`，连接 Home、Compose、Dashboard 和 Admin 的桌面导航、移动抽屉、上下文顶栏和用户状态。
- Home 改为 prompt-first 创建工作区，直接展示真实模板 JPEG；Auth 使用同一 token 和真实演示预览。
- Compose 改为资源栏、页面轨道、属性面板三段编辑器，并支持首页 brief/template query 预填、加载失败恢复和手机属性 sheet。
- Dashboard 改为任务局部导航、用户进度、16:9 渐进预览、批量下载、活动折叠区、运行诊断和不遮挡内容的手机聊天栏。
- Admin 接入共享壳，增加当前数据即时筛选、紧凑指标、sticky header 表格和响应式详情弹窗。
- 新增 `lucide-vue-next`；本轮触及页面已无手写 `<svg>`、装饰渐变和 emoji 图标。
- 删除 Dashboard 761 行、Admin 409 行已失效旧 CSS；实际设计系统记录在 `ppt-agent/frontend/design-system/ppt-agent/MASTER.md`。

## 8. 验证结果

- `npm run build`：通过，Vue 模板、TypeScript 和 Vite production build 无错误。
- Playwright + 本机 Chrome：Home、Auth、Compose、Dashboard、Admin 在 375、768、1024、1440 共 20 组截图检查，页面级横向溢出均为 0，`pageerror` 均为 0。
- 使用网络拦截注入本地样例数据，补查 Compose 有模板/有页面态、Dashboard 完成/预览态和 Admin 完整表格态；375、1440 均无横向溢出或运行时异常。
- 手机抽屉几何检查：主导航 `-245 -> 0 -> -245`，任务抽屉 `-326 -> 0 -> -326`；手机聊天栏参与布局，不覆盖幻灯片列表。
- 截图与浏览器报告保存在本地 `tmp/frontend-ui-audit/`，按仓库规则不提交。

本次 3100 Vite 服务未连接后端 API，因此真实浏览器空态检查会出现预期的 API 404/连接超时；错误均被页面错误态接住。完整数据态通过 Playwright route mock 验证，不改变生产代码和接口契约。
