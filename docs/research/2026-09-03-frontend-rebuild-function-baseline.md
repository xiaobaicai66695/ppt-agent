# 前端重构功能基线（重写前）

日期：2026-09-03  
状态：已冻结；旧实现已提交到 `acfc43e`，后续界面从零重建。

## 目的

本清单记录用户已经能够使用的前端能力。重构可以完全替换信息架构、组件和视觉语言，但不得静默丢失这些业务能力；每项在新实现中都需要有明确入口、状态和错误处理。

## 路由与身份

| 路由 | 现有能力 | 必须保留的行为 |
| --- | --- | --- |
| `/` | 创作入口与欢迎页 | 可进入对话/创建 PPT 的主入口；未登录时提供登录或访客体验路径 |
| `/auth` | 邮箱验证码登录、密码登录、访客登录 | 登录态持久化；访客独立用户隔离、退出后不可恢复的提示 |
| `/dashboard` | 统一对话、任务与交付工作台 | 查看、创建、继续和删除属于自己的会话/任务 |
| `/compose` | 高级 DeckSpec 编排 | 加页、布局选择、拖拽排序、编辑标题与布局、开始生成 |
| `/admin` | 管理员运营与诊断 | 非管理员不可访问；用户、任务、日志分析查看及日志删除 |

## 统一创作与对话

- 同一输入框可处理普通聊天、PPT 创建、规划草稿和已有任务修复。
- 用户可显式选择“PPT 生成”，或按需开启联网资料与图片参考；后端仍负责最终意图判定。
- 新会话会创建持久化的 conversation task；可把对话提升为 PPT 生成任务，任务 ID 保持一致。
- SSE 实时输出需支持逐段回答、工具调用、进度、文件、缩略图、token、错误和终态事件；断线或回放缺口需从会话快照恢复。
- Markdown 回答必须安全渲染，来源链接可点击，外部图片可预览；分块 SSE 不得损坏 URL。
- Unsplash 图片结果要显示图片来源、摄影师名和可点击的摄影师资料链接；链接必须包含 `utm_source=ppt_agent&utm_medium=referral`。
- 同步澄清、规划回答和 `answer_end` 后必须重新允许输入，不能遗留“提交中”状态。

## 任务与交付

- 会话列表显示标题、运行/失败状态、创建时间、token，并能新建、选择、删除。
- 任务页显示运行阶段、实时执行轨迹、工具/模型事件详情、失败信息、文件状态和 token。
- 生成中可逐页看到交付状态；完成后可预览缩略图、查看状态异常、下载 PPTX、取消任务或继续修改。
- 缩略图状态必须分别表达生成中、缺少缩略图、转换失败和文件不存在。
- 用户可在完成任务上提交 1–5 分反馈与建议；该操作不得触发重新生成。

## 高级编排

- 从 `/api/templates/layouts` 加载布局契约；根据 layout contract 展示必填项、容量和适用场景。
- 新建/复制/删除/移动页面；编辑标题、页面类型与组件计划；提交 `TaskOutline` 创建任务。
- 规划模式可保存并继续 `PlanDraft`，不应在用户确认前直接生成 PPT。

## 账户与管理

- 用户能查看、保存、替换和删除自己的模型供应商 API Key；界面只能显示掩码。
- 管理员可查看用户数、任务数、运行数，筛选用户/任务/日志，并查看详情和删除日志分析。

## 现有 API 契约

保留并复用 `frontend/src/api.ts` 中的服务端接口：鉴权、访客登录、任务 CRUD、消息路由、会话快照、继续生成、SSE、布局、草稿、账户 Key、交付反馈和管理员 API。页面重写不改变后端 HTTP 路径或 JSON 语义，除非另起后端变更。

## 新视觉方向

产品不是通用的“AI SaaS 面板”，而是把一个主题变成可交付叙事的演示工作室。

- **核心画面**：深蓝墨工作底色、象牙白投影片画布和萤光蓝绿“正在成稿”信号；用一张正在展开的投影片而不是抽象渐变作首屏主视觉。
- **首屏**：一句有张力的结果导向标题、可直接输入的创作框、动态演示页堆叠、可验证的流程指标。一个主行动入口，不堆多种 CTA。
- **交互**：输入框聚焦时画布回应；页面卡片在用户滚动或悬停时轻微展开；生成过程使用进度与页卡的状态变化，不做无意义循环动画。尊重 `prefers-reduced-motion`。
- **工作台**：采用“创作画布 + 可收起会话栏 + 交付轨迹”的层级；运行态是内容的一部分，而不是拥挤的仪表盘。
- **排版**：中文使用 `Noto Serif SC` 作展示字体、`Noto Sans SC` 作界面字体（加载失败回退系统字体）；大标题短促，正文行长受控。
