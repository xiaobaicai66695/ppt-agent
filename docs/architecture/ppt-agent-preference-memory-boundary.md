# PPT Agent 用户偏好记忆边界

更新时间：2026-08-24

本文档记录用户偏好记忆系统的当前决策边界，避免后续开发再次把模型生成结果、任务输出或 QA 分数写回用户画像，导致风格过拟合和跨场景污染。

## 1. 核心判断

用户偏好记忆只保留为**显式画像 + 只读参考信号**，不再承担自动学习闭环。

```text
保留：
- 用户确定性资料：姓名、组织、岗位、地区等
- 用户显式编辑的风格偏好：语言风格、页数倾向、品牌页脚、图表偏好等
- 同领域历史兼容数据的只读推荐
- 意图识别、领域判断和路由决策

删除/停用：
- 从已生成 PPTX 提取风格并写回画像
- 任务完成后根据 tasks.json、QA 分数或输出文件自动更新画像
- feedback/insights 自动学习接口
- Collector / Updater / Analyzer 后台学习链路
- 把模型生成时选择的模板、配色、背景反向沉淀为用户偏好
```

## 2. 职责边界

| 模块 | 当前职责 | 禁止职责 |
| --- | --- | --- |
| `pkg/agent/learning` | 意图识别、路由、读取画像并给出推荐 | 自动采集反馈、分析任务、更新画像 |
| `pkg/style` | 存储显式画像、读取历史兼容字段、按领域门控推荐 | 从任务或 PPTX 中提取偏好并合并 |
| `pkg/task` | 维护任务生命周期、conversation、runtime events、交付状态 | 在任务完成后学习模板、配色、布局或评分 |
| `pkg/web` | 提供画像查看、编辑、重置、摘要和推荐 API | 提供自动反馈学习或 insights 生成 API |
| 前端 API | 调用画像编辑和推荐接口 | 暴露已无后端支撑的 feedback/insights 调用 |

## 3. 提示词注入原则

提示词中的用户画像必须按优先级处理：

1. 当前用户显式要求优先。
2. 当前任务主题、受众、场景和推荐结果优先。
3. 用户确定性资料可直接注入，但当前任务另有说明时让位。
4. 语言风格、常用页数等低敏偏好只作为弱参考。
5. 模板、配色、布局、备注、成功模式等场景敏感偏好，只有同领域证据时才注入。

## 4. 为什么删除自动学习

PPT 生成链路中的模板、配色、背景和布局经常由 Planner 或 generator 为当前任务临时决策。把这些结果自动写回用户画像，会产生两个问题：

- 模型自我强化：一次不合适的生成结果会被当成用户偏好，下一次继续放大。
- 跨场景污染：例如技术汇报、旅游介绍、政务材料和个人简历的视觉偏好差异很大，不能互相迁移。

因此，用户画像只记录用户明确认可或手动维护的信息；系统生成结果仅作为本次任务的运行事实，不作为长期记忆。

## 5. 后续可恢复方向

如果未来重新做学习闭环，必须先满足以下条件：

- 学习源来自用户显式反馈，而不是模型生成结果。
- 每条学习记录带有场景、领域、置信度、时间和可撤销来源。
- 更新前有 Reviewer 或规则检查，禁止跨场景高敏偏好迁移。
- 前端提供可见的“记住/不要记住/删除记忆”控制。
- 画像写入和提示词注入有可测试 fixture。
